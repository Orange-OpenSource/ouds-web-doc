Modals

Modals are UI elements that interrupt the current page or task to focus the user's attention on a specific action, decision, or piece of information.

Overview

Component types

  • Title

    Content.

    Modal dialog is a temporary, surface-like UI element that interrupts the current page or task to focus the user's attention on a specific action, decision, or piece of information.

  • Title

    Content.

    Fullscreen dialog is a UI element that covers the entire viewport, interrupting the current page or task to focus the user's attention on a specific action, decision, or piece of information.

Approach

Modal dialog and fullscreen dialog use the same native <dialog> element with the .modal-base class. Either use .modal-dialog for a standard modal dialog or .modal-fullscreen-dialog for a fullscreen modal. The internal structure uses:

  • .modal-header for the header, it contains a .modal-title element for the main title.
  • .modal-body for the main content of the modal, it can contain a .modal-footer or not if using sticky actions.
  • .modal-footer for the action buttons for the modal.

The common variants are shared between modal dialog and fullscreen dialog, modal dialog has specific variants and sizes.

As this component relies on the native <dialog> element we encourage you to read the MDN documentation on the <dialog> element.

Heads up!

Interactivity

In this documentation we rely on invoker commands to trigger the opening, closing and light-dismissing of modals but you can also use JavaScript. Note that some browsers require a polyfill for full invoker commands compatibility.

Accessibility

As we use the native <dialog> element, we benefit from built-in accessibility features such as keyboard navigation, focus management, and screen reader support.

Some things to keep in mind while using modals include:

  • Ensure that the dialog has a meaningful and descriptive title, use the [aria-labelledby] attribute to reference the title element.
  • Choose the most appropriate initial focus when the dialog opens. By default, focus moves to the first focusable element; use [autofocus] when another element, such as the close button or an input, should receive focus.
  • Always provide an explicit and accessible way to close the dialog, such as a close, cancel, or confirmation button. Modal dialogs should also preserve the default Esc key behavior.
  • Open modal dialogs with showModal() or the show-modal invoker command so that the rest of the page is made inert and the dialog is exposed with modal semantics.
  • Adapt the title level to the context of the page, ensuring proper heading hierarchy.
  • Do not add [tabindex] to the <dialog> element.

Note

Read the MDN accessibility guidance for the <dialog> element for more information.

Modal dialog

A modal dialog is a temporary, surface-like UI element that interrupts the current page or task to focus the user's attention on a specific action, decision, or piece of information.

The modal dialog appears over a backdrop that visually separates it from the underlying content and blocks interaction with that content.

See the approach section to get an overview of the modal dialog structure and classes.

Variants

Fixed height

Add .modal-fixed-height to the <dialog class="modal-dialog"> to use the fixed height option. This variant can be used to define a fixed-height modal dialog for multi-step flows or content with a consistent layout. The modal dialog will use the maximum height available which depends on the modal size.

Rounded corner

Rounded corner modals is a project-wide option therefore all your modal dialogs should either be rounded or not. Add .use-rounded-corner-modal on a top container (for example <body>) to use rounded corners.

Heads up!

Rounded corners could be used in more emotional, immersive contexts or those tied to specific visual identities. For standard or business-oriented usage, keep the default square corners.

Note

We use a <div> as a parent container because we cannot use <body> in an example.

Fullscreen dialog

A fullscreen dialog is a UI element that covers the entire viewport, interrupting the current page or task to focus the user's attention on a specific action, decision, or piece of information.

The fullscreen dialog layout mirrors the structure and behavior of a standard page and lacks a backdrop, making it ideal for complex tasks or content needing more space and interaction.

Fullscreen dialog uses the same native <dialog> element and internal structure as modal dialog, use .modal-fullscreen-dialog on <dialog> to make it a fullscreen dialog. See the approach section to get an overview of the fullscreen dialog structure and classes.

Only the common variants are available for this kind of modal.

Using the grid

Use the OUDS Web grid system within a modal by adding .container-fluid and .container-max-width on .modal-header, .modal-body, and, if using sticky actions, .modal-footer. Then, use the normal grid system classes as you would anywhere else.

In this example the .col-* classes are highlighted with a background color, as a result their padding is visible and it seems the alignment is off. In reality their content are properly aligned within the grid system.

Switching types on breakpoints

For some use cases, it may be desirable to switch the modal type for example from a fullscreen dialog on smaller viewports to a modal dialog. This is not natively supported by the component, but OUDS Web exposes SCSS mixins that allow you to customize the modal behavior and appearance based on your needs.

The following example demonstrates how to define a .modal-fluid class to create a modal that adapts from a fullscreen dialog to a modal dialog based on the viewport size.

site/src/scss/_component-examples.scss 
.modal-fluid {
  @include modal-fullscreen-dialog();

  @include media-breakpoint-up(md) {
    @include modal-dialog();
  }
}

You can check the responsive behavior on the following example by resizing your browser window.

Actions layout

There can be up to three actions buttons on the modal. These buttons typically include a primary action, a secondary action, and an optional tertiary action, allowing users to confirm, cancel, or perform additional tasks related to the modal's content.

By default, the buttons will automatically stack vertically and grow to fill the available width on smaller screens. On larger screens, they will typically be displayed horizontally and aligned to the right with the tertiary action aligned left.

The actions focus order should follow a logical sequence, by default it follows the DOM order: first the primary action, followed by the secondary action, and finally the tertiary action if present. If you want more control on this, you can make the displayed order different from the DOM by using our order utility classes.

Note

As actions can be displayed in various ways depending on your needs, we rely on utility classes to achieve other layouts, such as horizontal alignment or buttons that are not full-width on smaller screens.

Interactivity

In order to open a dialog, you need to use either invoker commands or JavaScript.

When using showModal() or invoker commands on a <dialog> element, we benefit from built-in accessibility features such as keyboard navigation, focus management, and screen reader support, close on Esc key press. We do not need to implement these features manually.

Heads up!

Remember to always provide an explicit and accessible way to close the dialog, such as a close, cancel, or confirmation button.

Invoker commands

The Invoker Commands API provides a way to declaratively assign behaviors to buttons, allowing control of interactive elements when the button is enacted by the user. Please refer to the MDN article on Invoker Commands for more information.

We use this method in the examples above to open and close the modal dialogs without writing any JavaScript code.

Heads up!

As Invoker Commands are only recently widely available in browsers, it is recommended to integrate this polyfill in your projects or use the programmatic solution. See the polyfills section for more information.

First create a button with the [commandfor] attribute pointing to the ID of the modal dialog you want to control. The [command] attribute specifies the action to be performed, such as show-modal to open the dialog as a modal.

<button type="button" commandfor="modalDialogInvokerCommand" command="show-modal">
  Open modal
</button>

Then create a <dialog> element with the corresponding ID that matches the [commandfor] attribute of the button. Most of the time you should include the [closedby=any] attribute to allow closing the dialog by clicking outside of it (see light dismiss).

Heads up!

[closedby] attribute may not be supported in some older browsers. See the polyfills section for more information on how to mitigate this issue.

<dialog id="modalDialogInvokerCommand" class="modal-base modal-dialog" aria-labelledby="modalDialogInvokerCommandTitle" closedby="any">
  <h3 id="modalDialogInvokerCommandTitle" class="modal-title">Invoker modal dialog</h3>
  <!-- modal dialog content -->
</dialog>

Inside the <dialog> element, the buttons that should close the modal dialog need to have the [commandfor] attribute pointing to the ID of the dialog and the [command] attribute set to close.

<button type="button" class="btn btn-close" commandfor="modalDialogInvokerCommand" command="close">
  <span class="visually-hidden">Close</span>
</button>

Polyfills

Invoker commands are not supported by some browsers that are in OUDS Web target audience, add the invokers commands polyfill to enable this functionality.

This could be as simple as adding the following script tag in your HTML:

<script src="https://cdn.jsdelivr.net/npm/invokers-polyfill"></script>

The [closedby] attribute is also not supported in these browsers, and a polyfill may be required to enable these functionalities.

This could be as simple as adding the following script tag in your HTML:

<script src="https://cdn.jsdelivr.net/npm/dialog-closedby-polyfill"></script>

As explained in both polyfills readme files, if you are using npm, you can install the polyfills via npm and import them in your JavaScript files instead of including the script tags in your HTML.

import 'invokers-polyfill'
import 'dialog-closedby-polyfill'

JavaScript

JavaScript can be used to display and close the <dialog> element. You can use the showModal() method to display a modal dialog. The dialog can then be closed using the close() method. As demonstrated in the example below, you can also implement light dismiss functionality using JavaScript.

Light dismiss

Allow users to dismiss a modal by clicking outside when doing so will not discard their work or interrupt a required task. This behavior is known as "light dismiss" and can be enabled with invoker commands or implemented in JavaScript depending on which interactivity model you are using.

Note

Avoid light dismiss for dialogs with unsaved changes or required steps, and always provide a clear, accessible way to close the dialog.

Using invoker commands

Use the [closedby=any] attribute on the <dialog> element to enable light dismiss when you use invoker commands.

Heads up!

[closedby] attribute may not be supported in some older browsers. See the polyfills section for more information on how to mitigate this issue.

<dialog id="lightDismissModal" closedby="any" class="modal-base modal-dialog" aria-labelledby="lightDismissModalTitle">
  <!-- modal dialog content -->
</dialog>

Using JavaScript

For JavaScript we can implement light dismiss by listening for clicks outside the modal dialog and calling the close() method on the <dialog> element like this:

dialog.addEventListener('click', event => {
  if (event.target === event.currentTarget) {
    dialog.close()
  }
})

No light dismiss

Following is an example without light dismiss using invoker commands, [closedby="closerequest"] ensures that the dialog can only be closed programmatically or via the device closing request (on desktop this means pressing the Esc key).

Heads up!

[closedby] attribute may not be supported in some older browsers. See the polyfills section for more information on how to mitigate this issue.

If you are using JavaScript to control your modals just don't implement the click outside listener.
