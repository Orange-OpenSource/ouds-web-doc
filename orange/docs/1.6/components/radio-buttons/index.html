Radio button item

Radio button item is a UI element shaped like a row that allows users to select a single option from a set of mutually exclusive choices.

Unlike the standalone radio button, the radio button item accommodates a broader range of contexts by enabling the toggling of visibility of additional text labels and icon assets.

They are implemented using .radio-button-item and .control-item-* classes, see below. Browser default radio buttons are replaced with the help of the selector .control-item-indicator[type="radio"].

<fieldset class="control-items-list">

  <div class="radio-button-item">
    <div class="control-item-assets-container">
      <input class="control-item-indicator" type="radio" value="" id="radioButtonItemDefault" name="radioBasic" />
    </div>
    <div class="control-item-text-container">
      <label class="control-item-label" for="radioButtonItemDefault">Default radio button item</label>
    </div>
  </div>

  <div class="radio-button-item">
    <div class="control-item-assets-container">
      <input checked class="control-item-indicator" type="radio" value="" id="radioButtonItemDefault2" name="radioBasic" />
    </div>
    <div class="control-item-text-container">
      <label class="control-item-label" for="radioButtonItemDefault2">Checked radio button item</label>
    </div>
  </div>

</fieldset>

Approach

Control item

Control item is an abstraction for several non-text input components, like checkbox item, radio button item and switch item, that have similar behavior and layout. It contains an <input /> indicator, a text container for the label and an optional icon.

We use the parent element selector (:has) for all our <input /> states, like :invalid or :disabled. When combined with the .control-item-label class, we can easily style the text for each item based on the <input />’s state.

.control-item-assets-container controls the position of the .control-item-indicator and the optional icon.

.control-item-text-container contains the label and optional description and controls their positioning.

.control-item-label extend their clickable area until a .checkbox-standalone, .radio-button-standalone, .switch-standalone or a position: relative; is found in the page hierarchy. This ensures a consistent approach, whatever the DOM is. Consequently, none of the elements next to the label should be interactive.

.control-item-indicator uses customized icons to indicate checked states.

Control items list

As radio button items are almost always grouped in a list, they should be enclosed in a <fieldset> element with a .control-items-list class, this will handle automatic error text display when one of the control items input is invalid; you can add a <legend> element as a title for the list read more.

Accessibility

Max-width for accessibility

To maintain a clear visual hierarchy and ensure Assistive Technology users do not have to scroll back and forth across large areas of whitespace to understand what an action does, keep actions and meaningful icons physically adjacent to their descriptive labels. Make use of our component max-width utility to control the width of your components if needed.

Read only

To create a read only radio button item, the input should be replaced by a span element with role="radio" and aria-disabled="true" attributes. All the radio button items in the group must be surrounded by a container with role="radiogroup" and aria-readonly="true" attributes. This is the only way to be compliant with ARIA specifications. The radio button item will be accessible to keyboard navigation and assistive technologies, thanks to aria-labelledby and tabindex, but other interactions will be prevented.

Default readonly radio button item

Invalid

Note

The invalid state is the equivalent of the ‘Error’ state that you can find in the design specification.

Note

Prefer built-in form validation to handle client-side validation

When using semantic inputs and validation constraints attributes (like required, pattern...), the browser automatically adds a :user-invalid pseudo-class on invalid fields that OUDS Web will style.

Alternatively you can programmatically add a aria-invalid="true" to manually mark a field as invalid.

Read more in our form validation page for mandatory accessibility considerations.

To manually mark a radio button item as invalid, add the aria-invalid="true" attribute to a .control-item-indicator. An error icon will be automatically shown; if a decorative icon is specified, it will be hidden.

Layout

Default

It's recommended to keep radio button item labels to no more than three words. When space is limited or when a long label, extra label or description text is required, the text can wrap, as this is preferable to truncation. The radio button indicator and the icon will remain vertically centered, until the .control-item-assets-container reaches a defined maximum height.

Fieldset <legend>

For accessibility reasons, it is required to provide understandable radio button item labels without relying on visual context. It is also good practice to add a radio button item group title inside a <legend> element as the first child of the <fieldset> element. Screen readers will read the legend before navigating through the radio button items; this way, keyboard navigation users have more information on what is expected with the multiple radio button items element.

Radio button

Radio button is a UI element that allows users to select a single option from a set of mutually exclusive choices.

Radio button, that lacks an additional icon asset or text label, provides greater flexibility when designing other components that incorporate a radio button.

Heads up!

This standalone version is commonly used for building custom components and should not be used on its own. Remember to provide some sort of accessible name for assistive technologies (for instance, using aria-labelledby, a .visually-hidden, aria-label or a second label). See the forms validation accessibility section for details.

For the standalone radio button, we provide a completely different architecture than radio button item to ease the integration inside your projects.

<label class="radio-button-standalone">
  <input class="control-item-indicator" type="radio" value="" />
  <span class="visually-hidden">Default radio button</span>
</label>

Disabled

Add the disabled attribute to prevent interaction with the radio button and remove it from the keyboard tab order.

<label class="radio-button-standalone">
  <input disabled class="control-item-indicator" type="radio" name="standaloneRadioDisabled" value="" />
  <span class="visually-hidden">Disabled radio button</span>

html

Read only

Radio inputs do not support the readonly attribute. Replace the inputs with elements that have role="radio" and aria-disabled="true", and put them in a container with role="radiogroup" and aria-readonly="true".

<div class="radio-button-standalone" role="radiogroup" aria-readonly="true" aria-label="Read only radio button group">
  <span class="control-item-indicator" role="radio" aria-disabled="true" tabindex="0" aria-checked="true" aria-label="Selected option"></span>
</div>
html

Invalid

Note

Prefer built-in form validation to handle client-side validation

When using semantic inputs and validation constraints attributes (like required, pattern...), the browser automatically adds a :user-invalid pseudo-class on invalid fields that OUDS Web will style.

Alternatively you can programmatically add a aria-invalid="true" to manually mark a field as invalid.

Read more in our form validation page for mandatory accessibility considerations.

To manually mark a radio button as invalid, add aria-invalid="true" to the .control-item-indicator and use aria-describedby to associate an error message with it.

Heads up!

Contrary to control items, OUDS Web does not automatically add an icon or any other error indicator for the standalone controls, it only changes its color. This is because this component should be included in others (such as tables) and adding an icon could break some layouts.

Because color alone must not be used to indicate invalidity, provide an additional accessible indicator. In the example below, we add descriptive text and associate it with the control using aria-describedby.

Choose an available option.

<div>
  <label class="radio-button-standalone">
    <input class="control-item-indicator" type="radio" name="standaloneRadioInvalid" value="" aria-invalid="true" aria-describedby="radioButtonStandaloneError" />
    <span class="visually-hidden">Radio button</span>
  </label>
  <p id="radioButtonStandaloneError">Choose an available option.</p>
</div>
